# F0 — Documentação e Arquitetura

## Objetivo
Preparar a documentação e as decisões arquiteturais do Nexora antes da implementação de código de negócio.

## Instruções
Leia primeiro `MASTER_PLAN.md` na raiz do projeto.

Antes de alterar qualquer arquivo:
1. Inspecione o repositório.
2. Identifique o estado atual.
3. Não presuma que arquivos inexistentes existem.
4. Preserve alterações fora do escopo.

## Tarefas
- Criar/revisar `docs/architecture.md`.
- Criar/revisar `docs/roadmap.md`.
- Criar/revisar `docs/security.md`.
- Criar/revisar `docs/tenancy.md`.
- Criar/revisar `docs/billing.md`.
- Criar `docs/api-guidelines.md`.
- Criar os ADRs iniciais necessários em `docs/decisions/`.
- Registrar decisões sobre Modular Monolith, multi-tenancy, PostgreSQL, autenticação e separação de Billing.
- Verificar se a documentação está consistente com `MASTER_PLAN.md`.

## Restrições
- Não implementar funcionalidades de negócio.
- Não criar microservices.
- Não adicionar dependências desnecessárias.
- Não alterar código existente sem necessidade documental.

## Critérios de aceite
- Documentação inicial criada.
- Arquitetura claramente definida.
- Estratégia de tenancy documentada.
- Estratégia de segurança documentada.
- Billing separado do domínio operacional.
- ADRs relevantes registrados.
- Nenhum código de negócio implementado.

## Finalização
Informe:
- arquivos criados/alterados;
- decisões tomadas;
- conflitos encontrados;
- pendências para F1.

Não avance para F1.
