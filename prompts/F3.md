# F3 — Multi-Tenancy

## Objetivo
Implementar isolamento rigoroso entre tenants.

Leia `MASTER_PLAN.md`, `docs/tenancy.md` e inspecione o projeto.

## Entidades
Implementar:
- Tenant
- TenantUser
- TenantContext

Adaptar User/Role conforme necessário.

## Regras
- Um usuário pode pertencer a vários tenants.
- O tenant atual deve ser derivado do contexto autenticado.
- Não confiar no TenantId enviado pelo frontend como autoridade.
- Toda entidade tenant-scoped deve respeitar isolamento.
- Evitar vazamento por IDOR.

## Backend
Criar:
- resolução do tenant;
- contexto do tenant;
- filtros/repositórios seguros;
- seleção/troca de tenant quando necessário;
- autorização por tenant.

## Testes obrigatórios
Criar pelo menos dois tenants:
- Tenant A
- Tenant B

Com dados distintos.

Validar:
- usuário de A não lê dados de B;
- usuário de A não altera dados de B;
- usuário sem vínculo não acessa tenant;
- TenantId malicioso não contorna autorização.

## Critérios de aceite
O isolamento deve ser demonstrado por testes automatizados.

Não implementar clientes, agenda, billing ou pagamentos.

Finalize sem avançar para F4.
