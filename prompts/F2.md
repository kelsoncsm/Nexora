# F2 — Identity e Security

## Objetivo
Implementar autenticação e autorização de forma segura.

Leia `MASTER_PLAN.md` e inspecione o código atual.

## Entidades
Implementar conforme necessário:
- User
- Role
- Permission
- RolePermission
- RefreshToken

A relação com Tenant deve ser preparada para F3 sem duplicar regras.

## Backend
Implementar:
- cadastro;
- login;
- hash seguro de senha;
- JWT;
- refresh token;
- logout/revogação;
- autorização;
- roles;
- permissions;
- tratamento de erros de autenticação.

## Segurança
- Nunca armazenar senha em texto puro.
- Não registrar tokens/senhas em logs.
- Access token com duração adequada.
- Refresh token revogável.
- Validar issuer/audience/signature quando aplicável.
- Proteger endpoints.
- Configurar secrets via configuração segura.

## Frontend
- telas mínimas de login/cadastro;
- AuthService;
- interceptor;
- guard;
- armazenamento seguro compatível com a arquitetura escolhida.

## Testes
Testar:
- cadastro;
- senha inválida;
- login;
- token;
- refresh;
- logout;
- endpoint protegido;
- permissão insuficiente.

## Critérios de aceite
Usuário não autenticado não acessa endpoint protegido.
Usuário autenticado acessa somente operações autorizadas.

Não implementar tenancy completo, planos ou agenda.

Finalize sem avançar para F3.
